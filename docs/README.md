# Open_scraping 設計ドキュメント

**Open_scrapingは、完成品の使い方を固定して提供することよりも、利用者が改変・組み替えによって自分のソフトを作るための基盤を目指す。**

**コアは、部品を呼び出し、結果を渡し、定義された流れを実行するだけ。ブラウザ・検索・フィルター・ダウンロード・保存・データ処理・選別・出力の実装は、すべてコアの外に置く。**

コンセプト：Lang to Data by Web。標準の構成例として自然文からWebの画像・テキスト・統計／数表・動画を取得できるようにするが、その構成がコアの固定仕様ではない。

- 改訂日：2026-09-22（Asia/Tokyo）
- 状態：0.x基盤の実装開始。正式契約・検証器と開発基盤を先行し、実処理部品とフローランタイムは後続Issueで実装する。
- 標準構成の計画：0.xは基盤、1.0.0はテキスト・画像・統計／数表、1.1.0は動画。

## 責務の境界

| 部分 | 役割 |
| --- | --- |
| GUI／CLI | 入力・設定・結果の表示と公開APIの呼び出し。具体的な処理を実装しない |
| コア | フローの構造、呼び出し、接続、順序、分岐、並列、待機、中断、実行状態 |
| ホスト／実行環境 | 部品の登録・配送・プロセス・接続・権限を共通契約で提供 |
| 外部部品 | 検索、ブラウザ、各段階のフィルター、取得、保存、加工、選別、出力、言語解釈などの実処理 |
| 標準配布 | GUI・コア・ホスト・初期部品・フロー例を組み合わせた出発点 |

「外部」は責務の境界であり、外部サーバーを必須にする意味ではない。同じリポジトリ・配布物・プロセスにある内製コードでも、具体的な処理は部品として扱う。

**標準搭載は、最初からたまたま選ばれている実装にすぎない。** 標準・内製・他者製・商用・非商用でコアへの組み込みを正当化しない。

内製ブラウザと内製検索は、既存OSSを基盤に共通APIから操作できる部品として整備する。描画エンジンやWeb全体の検索基盤をゼロから作ることを初期要件にしない。

## この改訂で訂正したこと

前版の「検索・取得がコア、フィルターだけ追加機能」という区分を撤回した。検索・取得・保存・出力も外部部品であり、コアはそれらの内容を実装しない。

標準版の完成だけを目標にせず、利用者が部品、処理順序、画面、設定、配布構成を変えて自分のソフトを作れることを受入条件にした。共通処理であること、重要であること、高速化したいことだけを、コアへ具体的な処理を入れる理由にしない。

必要な部品を外したフローはその操作を実行できないが、コア自体は起動・検証できる。フィルターを使わないフローも正規の構成であり、未使用処理を暗黙に挿入しない。

**確定要件**は合意済みの方針、**実装案**は具体的なAPI名・値などの提案、**未決定**は今後決める事項を示す。
