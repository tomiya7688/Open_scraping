# ロードマップ・受入条件

[設計書一覧](README.md)

## 1. 現在の状態

この追加時点では設計文書のみであり、アプリ、検索アダプター、モデル、フィルター、公開APIの実装は含めない。以下の表は計画であって、リリース済み機能の一覧ではない。

## 2. バージョンの範囲

| バージョン | 確定した方向 | 基盤実装の案 |
| --- | --- | --- |
| `0.x` | テキスト・画像・統計の完成した収集機能は未実装 | 設定、API、プラグイン管理、ジョブ、停止・復旧、間隔制御、保存構造を試験用データで確認 |
| `1.0.0` | テキスト・画像・統計／数表に対応 | 検索、取得、出典保存、内製の初期選別モジュール、再選別、出力を一連の操作として提供 |
| `1.1.0` | 動画に対応 | 動画本体とメタデータ、保存・選別・出力、容量・長時間処理の制御 |

内製簡易ブラウザ、普段のブラウザとの拡張連携、SearXNG接続などは交換可能な実装として扱い、現時点で必須のリリース時期を約束しない。

## 3. 0.xの進め方

### 段階A：共通契約

設定スキーマ、ジョブ状態、プラグインAPI、保存モデルを先に決める。サイト指定・広域検索、ブラウザ選択、フィルター切り替え、手動／自動優先を保存して再読込できるようにする。

未実装機能は能力一覧とUIに未実装として表示する。試験用の検索・画像・数表データを返すモックは、実サイトから取得したデータとして表示しない。

### 段階B：実行制御

管理ブラウザの起動・停止・再読み込み・開き直しを接続部として試験する。応答しないワーカーを使い、UI・停止操作が巻き込まれないことを確認する。

要求間隔、同時数、検索先の配分、予算、中断・再開のテストを疑似時計と試験サーバーで行う。画像の意味判定より前に、負荷制御が守られることを確認する。

### 段階C：保存と再選別

取得・出典・解析・選別を別保存にし、試験用フィルターを差し替えて同じデータを再選別する。停止途中のファイルや保存障害から回復できることを試験する。

0.xでこれらの基盤を試験しても、三種類のデータ収集機能が完成したとは表現しない。

## 4. 1.0.0の到達条件

サイト内検索を先に試せ、必要に応じてユーザーが広域検索に切り替えられる。サイト・エンジンを追加し、複数検索先の配分を変更できる。

テキスト、画像、数表について、入力から検索、取得、出典保存、解析、選別、出力までの経路を用意する。数表から新しい統計を計算する機能の必須範囲は別途決める。

Google、DuckDuckGo、Bing、Yahooの接続プリセットを登録できる構造を整える。実際に使える接続方式を示し、外部事情で利用できないものを成功として扱わない。特定サイトでの検索成功は動作保証しない。

標準の品質・関連性・重複等の選別実装は公開APIを使う。ユーザーが無効化・交換・取り外しでき、無効なモジュールの推定を採否に流用しない。

## 6. 精度の評価

検索結果に含まれる正解の割合、正しい候補の取りこぼし、不要データを除外できた割合、正しいデータを誤除外した割合、判定保留率、処理時間、メモリを別々に測る。

画像テストには、対象単体、着用、他の物体との共存、横向き・全身、低解像度、部分的な遮蔽、イラスト・写真などを含める。主観語は唯一の正解があると扱わず、利用者が定義した採否例との差として評価する。

全体の類似度、衣服、キャラクター、画風などの条件別に測る。モデルの数値をそのまま人間の正解確率と呼ばない。合格閾値・評価枚数・基準データはモデル選定前の未決定事項とする。

## 7. 未決定事項

| 項目 | 現在の案／決めること |
| --- | --- |
| 対応OS | 最初に検証するOSと配布対象を決める |
| コア言語・UI | ローカル中心。具体的な言語・フレームワークは未採用 |
| ブラウザ接続 | Playwright管理ブラウザを初期候補とし、対応操作を検証する |
| 内製簡易ブラウザ | 既存エンジンの操作UIとして追加するか、時期を決める |
| 検索接続方式 | 標準エンジンごとに利用可能なブラウザ操作／APIを確認する |
| Yahooの地域 | 日本向けプリセットをYahoo! JAPANとするか明示する |
| モデル | 言語と画像のモデルを別選定。CPU／GPU、配布・取得方法、外部APIの扱い |
| 取得間隔等の初期値 | 試験で決める。設定例の数値をそのまま正式な既定値にしない |
| 動作防御の段階 | 標準・慎重等のプロファイル内容を決める。初期リンク選別とは別管理 |
| 実行中の設定変更 | runtime.mdの即時更新案を最初から採用するか、停止後変更に限定するか |
| プラグイン配布 | パッケージ、検証、権限表示、隔離、更新、互換性 |
| APIの安定化 | HTTP・通信方式、スキーマ、公開SDKと互換範囲 |
| 保存方式 | SQLite＋ファイルを候補とし、期限・容量・秘密情報を設計する |
| 統計の計算 | 1.0.0での数表取得に加え、派生集計をどこまで必須にするか |
| 動画形式 | 1.1.0の取得方式、コンテナ、コーデック、部分取得の範囲 |
| OSSライセンス | 本体・依存ライブラリ・モデル・プラグインを別に確認する |

## 8. 文書・実装の更新ルール

未決定を実装都合で確定扱いにしない。決定したら設計書と設定例を更新し、影響する要件IDと受入テストを対応付ける。

追加実装は標準部品と外部部品を同じAPIで試験する。検索サイトの一時的な動作確認と、本体契約のテストを分ける。失敗を記録し、停止・設定変更・再選別できることを継続して確認する。
