# データ契約と保存部品

[設計書一覧](README.md)

状態：設計。**コアはデータの参照と実行状態を運び、データ本体の取得・保存・解析・選別・出力は各部品が行う。**

## 1. 実行記録とデータセットを分ける

| 対象 | 所有する責務 | 例 |
| --- | --- | --- |
| 実行記録 | コアの汎用ランタイム。永続化はホストの状態ストア経由 | FlowRevision、Run、NodeRun、Operation、Event、チェックポイント参照、資源予算 |
| データセット | 保存・取得等の部品 | ファイル、取得URL、数表、発見・取得履歴、CollectionSnapshot |
| 派生データ | 処理・解析部品と保存部品 | 抽出本文、変換画像、スコア、キャプション |
| 選別・出力結果 | 選別・出力部品と保存部品 | 採否、選別版、出力ID一覧、ZIP等 |

コアの実行ジャーナルを持つことは、画像保存やCSV出力をコアへ戻す理由にならない。コアのDBスキーマにImage、SearchResult、Selectionのような業務固有テーブルを必須にしない。

実行ジャーナルの保存方式とデータセット保存方式は別々に交換できる案とする。実際のバックエンドは同じSQLiteでも別でもよいが、責務と移行を分ける。

## 2. 共通のDataRef

```json
{
  "type": "scraping.collection/v1",
  "provider": "storage",
  "ref": "collection-example",
  "revision": "1"
}
```

型、所有部品、識別子、版を参照として渡す案。大きな画像や動画をフロー設定や操作ログへ埋めない。コアは型宣言と配送先を確認し、本体の意味を解釈しない。

部品間で読めるよう、参照解決、読み取り権限、期限、破棄条件、永続化済みかを共通契約にする。単なるローカルファイルパスをリモート部品が同じように読めるとは仮定しない。

ダウンロード部品は一時参照の有効期間を保証し、保存部品のingest完了後に手放す。操作がsucceededでも参照寿命が切れれば再利用不能なことを表示する。再取得は別の明示操作。

## 3. 取得データの契約

以下は標準の取得・保存部品が共有するモデル案であり、コアの内部モデルではない。

| 記録 | 内容 |
| --- | --- |
| SearchRequest | 元入力、実検索語、検索方式、要求・有効条件、問い合わせ先 |
| Discovery | 掲載ページ、候補データURL、説明、順位、発見日時、検索要求 |
| FetchAttempt | 初期URL、到達先、取得時刻、応答、転送量、成功／失敗 |
| Blob | 内容ハッシュ、形式の観測、サイズ、保存状態、本体参照 |
| Item | 種類、Blobや構造化値、取得・抽出したメタデータ |
| ItemDiscovery | 同じItemに対する複数の発見経路 |
| CollectionSnapshot | 固定した取得項目ID集合と版 |

同じURLでも時点で内容が変わるため、URLのみをデータの主キーにしない。同じ画像が複数サイトにあれば出典を複数残す。内容ハッシュで本体を共有しても発見経路は捨てない。

取得元は原作者や最初の公開元と同じとは限らない。掲載された作者・条件・出典は観測として保存し、モデルの推定と別にする。W3C PROVを来歴設計の参考とするが、完全準拠は未決定。[S11](references.md#s11)

## 4. 保存・整合性の担当

初期保存部品の候補はSQLite＋ローカルファイル。書き込みの取りまとめやトランザクションは保存部品内で行い、コアにSQLや画像用テーブルを置かない。SQLiteの適用範囲・並行性は採用時に確認する。[S10](references.md#s10)

ダウンロードと保存は一時ファイル、完成状態、チェックポイントを協調して扱う。保存が確定していないのに完了参照を返さず、中断ファイルを正常画像にしない。クラッシュ時の孤立ファイル・未確定レコードの照合も保存部品の責務。

ノード終了と永続化完了は同じとは限らないため、保存契約のcommit済み応答を定義する。コアはその応答を記録して次の依存ノードを呼ぶ。

取得成功、デコード不能、解析失敗、条件不一致を分ける。壊れた画像の選別部品を使わなくても、実処理の失敗を成功に変換しない。

## 5. 解析・選別は別の記録

| 記録 | 内容 |
| --- | --- |
| Artifact | リサイズ、切り出し、要約等と元データ・生成処理 |
| Analysis | 値、根拠、モデル・部品版、入力参照、設定、エラー |
| DuplicateGroup | 比較方式、距離、閾値、グループ化・代表選択 |
| SelectionRevision | 対象集合、条件、各項目の採用・除外・保留 |
| ManualOverride | 手動の訂正内容と時刻 |
| ExportManifest | 実出力ID・ハッシュ、出典、変換・選別版、出力日時 |

選別を実行しなければSelectionRevisionは不要。全て採用したダミーの選別版を作らず、CollectionSnapshotを出力部品へ直接渡す。

保存したスコアに対して閾値だけ変更する場合、選別部品で再計算し、再取得や画像再解析を必須にしない。解析キャッシュは内容、前処理、モデル・部品版、設定をキーにする。

近似重複とバイト一致を分ける。AとB、BとCが似ている場合のグループ規則を明示し、代表選択を利用者が確認できるようにする。

衣服・キャラクター・画風・構図の一致は別の判断材料にする。「Tシャツがある」に対してスカートの共存だけで除外する処理を勝手に加えない。多数派と違う正しい画像を落とした割合も評価する。

## 6. データ種別は部品・契約で拡張する

| 製品版 | 対象 | 部品が扱う情報 |
| --- | --- | --- |
| 1.0.0 | テキスト | 原文・抽出本文、言語、文字コード、抽出元 |
| 1.0.0 | 画像 | 本体、サイズ・形式、掲載／取得URL、サムネイル等の区別 |
| 1.0.0 | 統計／数表 | 掲載値、列、型、単位、対象期間、母集団・分母の記載、欠損、出典 |
| 1.1.0 | 動画 | 本体、長さ・形式、掲載／取得URL、派生フレーム・クリップの関係 |

サムネイルしか取れていないのに原画像と呼ばない。本文抽出とモデル要約を分ける。数値正規化や単位変換は元表記と処理根拠を残す。

掲載された統計の取得と、新しい統計の計算は別。派生集計を行う部品は入力ID集合、式、欠損・重複の扱いを記録し、途中収集の値を全体統計と表示しない。

動画追加のためにコアへコーデックやフレーム抽出を組み込まない。配信方式やファイル対応は部品の能力として決め、未対応方式を扱えるとは表示しない。

## 7. 出典条件・秘密情報

商用利用条件や研究向けの出典評価は、その部品を使う場合の判断材料。「記載を観測」「不明」「矛盾」と判定を別にし、モデルだけで利用許可を保証しない。

認証情報、クッキー、署名付きURL等の秘密情報と、共有する出典を分ける。保存・出力部品が公開用情報を定義し、ホストは資格情報のアクセス権を管理する。秘匿化した事実を残す。

## 8. 出力と取り外し

出力部品はCollectionSnapshotまたはSelectionRevisionの対応型を受ける。前者に選別履歴を要求しない。標準のファイル＋マニフェスト出力もコア内蔵ではなく、標準同梱の出力部品である。

解析・選別部品を取り外しても、元データを読める保存・出力部品があれば直接出力できる。保存部品を取り外した場合、データファイルが残っていても別の部品で読めるとは限らない。移行形式・互換リーダーを公開する。

完全削除、保存期限、容量整理は保存部品の明示操作。選別の除外とは分け、共有Blobや過去出力への影響を表示する。実データが削除済みなら、同じ内容を再出力できると保証しない。
