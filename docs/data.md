# データ保存・選別

[設計書一覧](README.md)

R10・R11の実装案。取得データと出典を保持し、解析や採否を後から変更できることを中心にする。ここでの保存は無期限保存を意味せず、保存期限・容量・削除設定を別に持つ。

## 1. 四つの情報を分ける

| 層 | 内容 | 扱い |
| --- | --- | --- |
| 取得したもの | ファイル本体、レスポンスから得た本文・数表等 | 元データとして参照する |
| 観測した情報 | 発見元、取得URL、日時、要求・応答情報、掲載された説明 | モデル推定と区別する |
| 推定・加工した情報 | タグ、類似度、本文抽出、形式変換、重複候補 | 生成処理と版を記録する |
| 選択した結果 | 採用、除外、保留、適用ルール、手動訂正 | 選別版として保存する |

出典・加工の来歴を扱う考え方としてW3C PROVを参考にするが、初期保存形式をPROVに完全準拠させることまでは決めていない。[参考 S11](references.md#s11)

## 2. 論理データモデル

| オブジェクト | 主な項目 |
| --- | --- |
| `Job` | ID、元入力、設定版、状態、開始・終了、予算消費 |
| `SearchRequest` | 検索先、検索方式、実検索語、要求条件、有効条件、継続情報 |
| `Discovery` | 発見ID、検索要求ID、掲載ページ、データURL候補、順位、説明、発見日時 |
| `FetchAttempt` | 発見ID、操作ID、初期URL、到達先、時刻、ステータス、転送量、失敗理由 |
| `Blob` | 内容ハッシュ、保存先、バイト数、型の観測値、保存状態 |
| `Item` | データ項目ID、種類、Blob参照、構造化内容、メタデータ |
| `ItemDiscovery` | 同一項目に対応する複数の発見記録 |
| `Artifact` | サムネイル、抽出本文、変換画像等の派生データと生成処理 |
| `Analysis` | 項目ID、プラグイン・モデル版、入力参照、設定、値、根拠、エラー |
| `DuplicateGroup` | 重複方式、グループ、比較根拠、代表選択ルール |
| `SelectionRevision` | 対象項目群、ルール、閾値、未判定方針、各項目の採否 |
| `ManualOverride` | 選別版、対象項目、訂正内容、時刻 |
| `Export` | 出力ID、選別版、確定した項目ID一覧、形式、完了状態 |
| `Event` | 順序番号、操作、状態遷移、設定変更、復旧、失敗 |

URLが同じでも取得時点によって内容が変わり得るため、URLだけをデータの主キーにしない。同じファイルを別の場所で見つけても、一つのURLで上書きせず発見記録を複数関連付ける。

## 3. 保存処理

### 3.1 本体と管理情報

単一PC向けの初期案は、管理情報をSQLite、本体ファイルをローカル保存とする。SQLiteはローカルアプリ向けに利用できるが、書き込み並行性には制約があるため、コアで書き込みを取りまとめる案とする。[参考 S10](references.md#s10)

この方式は採用確定ではなく、複数ユーザーが同時利用するサーバー構成を初期前提にしない。

### 3.2 途中ファイルを完成品にしない

本体は一時保存し、取得の完了とハッシュ・サイズ等を確認後に完成状態へ移す。メタデータ登録とファイル確定の間で停止しても回復できる状態を持つ。

起動時は、登録途中のファイル、ファイルのない参照、完成扱いになっていない残存ファイルを照合する。停止やブラウザ再起動で途中データを正常画像として出力しない。

取得完了後に形式を解析できなかった場合は、取得成功と形式解析失敗を別記録にする。壊れた画像の除外フィルターを外しても、解析失敗を正常画像と偽ることにはならない。

### 3.3 元データと変換

元画像、リサイズ画像、切り出し画像、サムネイルは別のオブジェクトにする。抽出した本文と取得ページも別にする。変換で元ファイルを上書きしない。

保存するHTMLや応答情報の量は容量設定で調整可能にする。保存していない情報を「後から完全再現できる」と表示しない。

## 4. 出典と根拠

掲載ページ、データURL、初期リンク、到達先URL、検索サービス、検索文、取得日時を区別して記録する。

掲載されたライセンス名・利用条件・作者表記は、観測した文字列、参照URL、確認日時とともに残す。モデルによる解釈は別の `Analysis` とする。

例えば「非商用条件の表記を観測した」「条件を見つけられなかった」「情報が矛盾する」は別状態にする。商用利用の許可や法的適合性を、モデルの推定だけで保証しない。

研究向けの信頼性は、原資料に遡れるか、方法が記載されているか、取得日時があるかなど、利用者が選べる観点に分ける。特定のサイト名から万能の信頼性スコアを付ける仕様にはしない。

署名付きURL、認証情報、クッキー等は通常の出力へ混ぜない。必要な原記録のローカル保持と、共有用の秘匿化済み表示を区別する。秘密情報を除去した場合は除去の事実を記録し、完全な原URLを保存したと誤認させない。

## 5. 重複

### 5.1 完全一致と近似一致

バイト単位で同一なファイルの検出と、見た目が似ている画像の検出は別の解析・選別にする。

保存効率のために同じBlobを共有することと、データセットから項目を除外することも別である。完全一致フィルターが無効でも、同じBlobへの参照を複数の発見記録から持てる。

近似重複では比較方法、距離、グループ化方式、閾値を記録する。AとB、BとCが似ていてもAとCが同程度に似ているとは限らないため、グループ化方式を隠さない。

### 5.2 代表項目

重複グループから代表を選ぶ場合は、解像度、取得順、ユーザー指定の出典優先等、選択ルールを表示する。フィルターを無効にすれば、保存されている別項目を再び出力候補にできる。

## 6. 類似度と条件一致

検索文との全体的な類似度、指定衣服の存在、画風、キャラクターの一致、画質を別の値として扱う。異なる目的を一つの不透明な数値にまとめない。

「Tシャツを含む画像」ではTシャツの有無を確認する。スカートが同時に写るだけでは除外しない。「Tシャツの商品単体」なら着用写真は別条件で不一致になり得る。解釈された条件に基づいて理由を表示する。

LoRA等の学習用では、揃えたい特徴と変わってよい特徴を分ける。衣装が対象なら別のキャラクターでも一致する可能性があり、キャラクターが対象なら衣装の違いを勝手に不一致にしない。

参照画像や手動採否を使う場合はユーザーの明示操作として記録する。集まった多数派を無条件に正解として学習し直す設計にはしない。自動の品質評価を使う場合も正しい画像を捨てた割合を測る。

## 7. 再選別

通常の後処理は新しい `SelectionRevision` を作る。除外した理由、使ったスコア、閾値、手動訂正を辿れるようにする。

| 変更 | 必要な処理 |
| --- | --- |
| 保存済みスコアの閾値 | 選別だけ |
| フィルターの有効／無効 | 選別の再計算。未計算の解析が必要なら明示する |
| 画像解析モデル | 対象の再解析と再選別 |
| 検索条件・検索先 | 別の検索実行。既存データへの適用は独立して選ぶ |
| 出力形式 | 同じ選別版から再出力 |

キャッシュキーにはデータの内容ハッシュ、前処理、モデル・プラグイン版、解析設定を含める。古いモデルの数値を新しいモデルの結果として使わない。

手動訂正を次の選別版にも引き継ぐかは設定にする。過去の選別版を勝手に書き換えない。判定不能・未実行・失敗の対象を確認できるようにする。

## 8. 種類別の保存と出力

### 8.1 テキスト（1.0.0）

抽出本文、タイトル、言語、文字コード、掲載URL、抽出処理を保持する。原文の引用・抽出とモデルによる要約を区別する。出力候補はTXT、Markdown、JSONL、表にできる項目のCSVとする。

### 8.2 画像（1.0.0）

本体、幅・高さ、形式、掲載URL、データURL、説明やタグを保持する。検索サムネイル、表示用画像、高解像度候補を区別し、サムネイルしか取得していないものを「原画像」と呼ばない。

画像フォルダー／ZIP、メタデータCSV／JSONL、項目ごとの説明用テキストを出力候補にする。ZIP等の対応形式はロードマップで実装範囲を確定する。生成キャプションは掲載元の説明と別の派生情報として保存する。

### 8.3 統計・数表（1.0.0）

掲載された数表の取得と、集めたデータからの計算を分離する。元の値、正規化後の値、型、単位、通貨、対象期間、母集団・分母、欠損、出典を持つ。

計算する場合は入力の項目ID一覧、重複の扱い、欠損処理、式・集計方法を記録する。収集が途中の集計を全体の統計と呼ばない。計算機能の必須範囲は未決定だが、数表の取得・保存・出力は1.0.0の対象である。

### 8.4 動画（1.1.0）

元動画、長さ、形式、派生サムネイル・フレーム・クリップ、切り出し位置の関係を保存できる形にする。0.xでは動画の処理を実装せず、データ種別を後から追加可能にする。

1.1.0の初期案は取得可能な動画ファイルを対象にし、ライブ配信、DRM解除、サイト固有の複雑な配信方式への対応は自動的に含めない。動画では容量・通信時間・再開方式の受入条件を別途追加する。

## 9. 出力マニフェスト

出力時には、項目ID一覧と内容ハッシュ、出典、取得日時、選別版、適用フィルターと設定、モデル版、変換履歴、出力時刻を含むマニフェストを保存する。

選別条件だけを保存しても、後で元データが増えれば選ばれる項目が変わるため、実際に出力したID集合も固定する。選別条件からの再生成と、同一出力の再現を区別する。

## 10. 削除と保存期限

フィルターを無効化しても過去の解析・選別履歴を消さない。フィルターを取り外した場合、過去の結果は閲覧できるが同じ処理を再実行できない可能性を表示する。

完全削除と保存期限は選別から独立した操作・設定にする。Blobが他の項目から参照されている場合の削除対象を確認し、共有Blobを不用意に失わせない。元データが削除済みなら、その再選別・再出力ができないことを示す。
