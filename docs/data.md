# データ保存と任意の解析・選別

[設計書一覧](README.md)

R10・R11・R20〜R22の実装案。**取得データは解析・選別結果なしで保存・閲覧・出力できる。** 追加処理は元データとは別に結果を保存する。

## 1. 取得データと追加情報

| 区分 | 内容 | 生成条件 |
| --- | --- | --- |
| 取得本体 | ファイル、本文、掲載された数表等 | コアが取得・抽出した場合 |
| 取得記録 | 発見元、検索要求、掲載・取得URL、日時、成功・失敗 | 検索・取得に応じて生成 |
| 解析・加工情報 | 類似度、タグ、重複候補、生成キャプション等 | 対応する追加機能を使った場合だけ |
| 選別情報 | 採用・除外・保留、ルール、閾値、手動訂正 | 選別機能を使った場合だけ |

後ろの二つが空でも正常である。取得項目を自動的に「採用済み」と分類せず、単に取得結果として扱う。

来歴の表現にはW3C PROVの考え方を参考にするが、初期形式の完全準拠は未決定。[参考 S11](references.md#s11)

## 2. コアの保存モデル

| オブジェクト | 主な項目 |
| --- | --- |
| `Job` | 取得設定版、状態、開始・終了、消費予算 |
| `SearchRequest` | 検索先、方式、実検索語、要求／有効条件、継続情報 |
| `Discovery` | 検索要求、掲載URL、データURL候補、順位、説明、発見日時 |
| `FetchAttempt` | 操作ID、初期URL、到達先、応答、転送量、失敗理由 |
| `Blob` | 内容ハッシュ、保存先、バイト数、型の観測、保存状態 |
| `Item` | データ項目ID、種類、本体参照、取得・抽出したメタデータ |
| `ItemDiscovery` | 同じ項目と複数の発見経路の関連 |
| `CollectionSnapshot` | ある時点の取得項目ID集合と取得設定版 |
| `Export` | スナップショット、実出力ID・ハッシュ、形式、保存先、状態 |
| `Event` | 操作、状態遷移、設定変更、復旧、失敗の順序付き記録 |

`Item`、`Job`、`CollectionSnapshot`、コアの`Export`は、解析ID・選別IDを必須参照しない。追加機能のテーブルが存在しなくても、コア用スキーマだけで動作する。

URLだけを本体の主キーにしない。内容が同じでも発見元を上書きせず、同じURLの内容が変わった場合も別の取得記録を残す。

## 3. 追加機能側の保存モデル

| オブジェクト | 主な項目 |
| --- | --- |
| `Artifact` | リサイズ、切り出し、要約等と生成処理 |
| `Analysis` | 入力項目、モデル・プラグイン版、設定、値、根拠、エラー |
| `DuplicateGroup` | 比較方式、グループ、距離、代表選択規則 |
| `SelectionRevision` | 入力項目集合、条件、閾値、未判定方針、各項目の採否 |
| `ManualOverride` | 選別版、項目、訂正内容、時刻 |
| `SelectionExport` | 選別版、実出力ID集合、変換履歴、出力記録 |

追加情報がコアの項目IDを参照する方向とする。逆方向の必須依存は設けない。同一DBを選ぶ場合でも、追加テーブルの初期化・移行をコアの起動条件にしない。別DB・名前空間等の配置は実装時に決める。

## 4. 保存・停止・失敗

単一PC向けの候補はSQLiteに管理情報、ファイルシステムに本体を保存する方式。SQLiteの書き込み並行性を考慮してコアで更新をまとめる案とする。[参考 S10](references.md#s10)

一時ファイルから取得完了を確認して本体へ移し、メタデータ確定とファイル確定の途中で停止しても回復できる状態を持つ。起動時に残存ファイル・参照切れを照合する。

取得成功、通信中断、形式解析失敗を分ける。バイト取得が成功しても画像として読めない場合、その観測を記録する。未完成ファイルを正常データに見せないことは、任意の品質選別を必須化することではない。

必要な本文・表・形式情報の抽出と、「用途に適しているか」の選別を区別する。元データを変換で上書きせず、保存していない原ページを完全再現できるとは表示しない。

## 5. 出典・観測・推定

掲載ページ、データURL、初期リンク、到達先、検索先、検索文、日時を別記録にする。作者・ライセンス・利用条件は観測文字列、参照URL、確認日時を保存できる構造にする。

観測された情報から商用利用可否や出典の信頼性を判断する機能は追加解析である。「条件の記載を見つけた」「見つからない」「矛盾する」と、モデルによる結論を分ける。モデルだけで法的な利用許可を保証しない。

研究向けの出典追跡性や方法記載の有無も、利用する場合に項目別の追加評価として扱う。取得成功を信頼性認定としない。

署名付きURL、認証情報、クッキー等は共有用出力へ混ぜない。原記録と秘匿化済み表示を区別し、省略の事実を残す。秘密情報の保存・公開範囲は任意のデータ品質フィルターとは別に管理する。

## 6. 重複と計数

内容ハッシュで同じBlobを共有する保存方式や、一意な取得件数の計数は、近似画像を除外する選別とは別である。保存共有しても、異なる発見経路・要求を捨てない。

完全一致・近似一致をデータセットから間引く機能は追加フィルターにする。比較方法、距離、閾値、グループ化、代表選択を記録する。AとB、BとCが似ているだけでAとCも同じ程度に似ているとは仮定しない。

解像度・取得順・出典等による代表選択は、使用した選別のルールとして表示する。コアの直接出力をそのルールに依存させない。

## 7. 条件一致・再選別

画像の全体類似度、衣服、キャラクター、画風、画質を、利用者が選ぶ別の解析値として扱う。「Tシャツを含む」条件でスカートの共存を自動的に不一致にしない。揃える特徴と変わってよい特徴を分ける。

主観語や参照画像を使う場合は基準・手動採否を記録する。多数派を無条件に正解として扱わない。モデルの精度と誤除外を測り、取得基盤の成否とは別に評価する。

| 変更 | 処理 |
| --- | --- |
| 保存済みスコアの閾値 | 追加機能側で再選別 |
| フィルターの有効／無効 | 選別版の更新。必要な未計算解析は明示 |
| 解析モデル | 対象データの再解析・再選別 |
| 検索先・検索語 | 別の取得実行 |
| 出力形式 | 指定スナップショットまたは選別版から出力 |

解析キャッシュは内容ハッシュ、前処理、モデル・プラグイン版、設定を含める。古い数値を新モデルの結果として使わない。手動訂正を引き継ぐかは選別設定にし、過去の選別版を上書きしない。

後処理を変更しただけでWeb再取得を始めない。追加収集は、ユーザーが選んだ別のワークフロー操作とする。

## 8. データ種別

| 種類 | 取得側で保持するもの | 任意の追加処理例 |
| --- | --- | --- |
| テキスト（1.0.0） | 原文・抽出本文、タイトル、言語、出典、抽出方法 | 要約、分類、関連度、信頼性評価 |
| 画像（1.0.0） | 画像本体、形式・サイズの観測、掲載／取得URL、掲載説明 | 類似度、タグ推定、重複選別、生成キャプション |
| 統計・数表（1.0.0） | 掲載値、列、単位・期間・母集団等の記載、欠損、出典 | 新しい集計、補完、品質評価、正規化の追加処理 |
| 動画（1.1.0） | 動画本体、長さ・形式の観測、掲載／取得URL | クリップ、フレーム抽出、分類、重複選別 |

画像は検索サムネイル・表示用・高解像度候補を区別する。サムネイルしか取れなかったものを原画像と呼ばない。

数表の抽出時に型を読み取った場合も元の表記を残す。新しい統計を計算する場合は追加処理として入力ID、式、単位、欠損・重複の扱いを記録する。収集途中の集計を全体の統計と表示しない。

0.xでは各種収集を完成機能として実装せず、データ種別を追加できる保存契約を作る。動画の初期案は取得可能なファイルを対象にし、ライブ配信やDRM解除を自動的に対象へ含めない。

## 9. 選別を経由しない出力

コアは`CollectionSnapshot`を作り、その時点の取得済み項目IDと本体・出典を直接出力する。マニフェストは取得設定版、実出力ID、ハッシュ、取得元・日時、出力日時を含む。

**選別版・フィルター・モデルの情報は必須ではない。** コア出力に存在しない判定やモデル名を作らない。取得項目の列挙と、内容の合否判定を区別する。

追加機能で選別した出力は`SelectionExport`として選別版、実際のID集合、フィルター・モデル版、変換を追記する。どちらの出力かをUIで選べる。

条件だけでは元データ追加時に結果が変わるため、実際の出力ID集合を固定する。基本のファイル・マニフェスト出力と、TXT・Markdown・CSV・JSONL・ZIP等の追加対応範囲をリリースごとに明示する。

## 10. 取り外し・削除・保存期限

フィルターを無効化・取り外しても元の取得データは残る。過去の追加結果は参照用に維持でき、同じ実装がなければ再計算できないことを表示する。直接出力は引き続き使える。

通常の除外は選別結果だけを変える。完全削除・保存期限・容量上限は別設定にし、共有Blobや参照先への影響を確認する。削除済みデータを再選別・再出力できるとは表示しない。
