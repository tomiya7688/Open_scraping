# 共同開発・コントリビューション手順

[開発者向けトップ](README.md) · [開発ガイド](development-guide.md)

この文書は Open_scraping へ参加する際の**提案プロセス**です。誰でも Issue や PR で提案できますが、採用・マージはレビューを経て行います。書き込み権限や自動マージの存在を保証するものではありません。

## 1. Issue から着手する

1. [既存 Issue](https://github.com/tomiya7688/Open_scraping/issues) と [全体計画 #1](https://github.com/tomiya7688/Open_scraping/issues/1) を確認し、二重実装を避ける。
2. 機能・バグ・研究・文書のいずれかを明記し、現状、期待結果、受入条件、影響する層を書き出す。
3. 大きな提案は、契約変更/ランタイム変更/部品/UI/文書など独立レビューできる単位へ分割する。
4. 前提となるIssueやPR、対象版（0.x、1.0.0、1.1.0）を示す。未確定事項は確定仕様にしない。

すでにIssueがある作業は新たな重複Issueを作る必要はありません。意見や質問も関連Issueのコメントを利用できます。

## 2. 開発する

```bash
git clone https://github.com/tomiya7688/Open_scraping.git
cd Open_scraping
git checkout main
git pull --ff-only
git switch -c feat/issue-番号-短い説明
npm install
npm run verify
```

上のブランチ名は例です。直接push権限がない場合はフォークからブランチを切ってPRを送ります。例示の `番号` は担当Issueに置き換えます。

**実装の原則：** 既存テストを維持し、変更した振る舞いのテストを追加する。公開契約/型の変更を隠さない。標準部品のための特別分岐をCoreへ入れない。不要な大規模整形やファイル移動を機能PRに混在させない。

## 3. PRを出す

PRには次の事項を含めます。

- 対応 Issue 番号、解決する問題、変更の範囲と対象外
- Core / Host / Contracts / Component / UI への影響と破壊的変更の有無
- 再現手順、テストコマンド、実測した結果（未実行は未実行と書く）
- 契約・サンプル・利用者ドキュメント・開発者ドキュメントの更新内容
- 依存PR、レビュー順序、スクリーンショットや再現データ（必要な場合）
- OSや実サービスでの動作を試していない場合、その制限

`Closes #番号` はPRが受入条件を満たすときだけ記載します。部分実装は `Refs #番号` として残作業を明示します。

## 4. レビューとマージ

- author自身が [コードレビューガイド](code-review.md) を確認し、CI の `npm run verify` を通します。
- レビュアーは意図、責務境界、停止と再送、権限、error状態、データ寿命、テストの妥当性を確認します。
- 未レビュー・CI失敗・未実装の受入条件を「完了」にしません。マージ権限者が最終判断します。
- 大きな設計決定・互換性の変更は、Issue/ADR に判断理由、代替案、影響を残します。
- 無関係な変更・整形をPRに混在させず、レビュー可能な差分に保ちます。

## 5. 秘密情報、利用条件、ライセンス

- ログ、スクリーンショット、Issue本文にcookie、APIキー、資格情報、個人情報を載せないでください。公開Issueへ秘密を貼り付けないでください。
- 検証はモックや管理可能な試験ページを優先し、実サイト・外部SDK・取得データの条件や権利関係を確認してください。
- **プロジェクト全体のライセンス/配布方針は [Issue #3](https://github.com/tomiya7688/Open_scraping/issues/3) で検討中**です。このガイドは再利用・再配布の権利許諾ではありません。第三者コードを追加する前に権利関係・ライセンスを確認し、不明点をIssueで相談してください。
- セキュリティ上の機密を含む報告は、公開Issueに詳細を載せず、利用可能な非公開連絡方法についてリポジトリ管理者へ確認してください。

## 6. 文書だけの貢献

誤記、リンク切れ、現在の機能と設計予定の混同も歓迎する修正対象です。[文書運用ルール](documentation.md) に従い、利用者/開発者どちらの読者向けなのかを明確にします。文章のみのPRでも `npm run check:docs` を実行してください。
