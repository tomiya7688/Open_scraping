# AIアシスタント共通開発・引き継ぎガイド

[共通規約（AGENTS.md）](../../AGENTS.md) · [リポジトリ入口](../../README.md) · [ドキュメント目次](../README.md)

## 目的

ChatGPT、Claude（チャット）、Claude Code、Codex、GitHub Copilot が **同じリポジトリの設計原則・Issue・PR・検証結果** を根拠に共同開発できるようにします。

**規約の正本はルートの [AGENTS.md](../../AGENTS.md) のみ**です。AI固有ファイルには別の実装方針を作りません。AIに自動で取り込まれるかどうかは、実行モード、ワークスペース、バージョン、接続権限によって異なります。

## ツールごとの読み込み

| ツール | リポジトリ側の入口 | 利用者が確認すること |
| --- | --- | --- |
| Codex（CLI / IDE等） | `AGENTS.md` | 作業対象のリポジトリを開き、読み込まれた指示を確認 |
| Claude Code | `CLAUDE.md` の `@AGENTS.md` import | プロジェクトルートから実行し、`/context` 等で読み込みを確認 |
| GitHub Copilot | `.github/copilot-instructions.md` と対応環境の `AGENTS.md` | リポジトリ指示の利用が有効か確認。Agent・IDE・GitHub上のモードで挙動は異なる |
| ChatGPT（通常チャット） | `AGENTS.md` を明示的に指定 | 対象GitHubリポジトリを接続・選択するか、ファイルを添付し、毎タスクの関連Issue/PRを渡す |
| Claude（通常チャット） | `AGENTS.md` を明示的に指定 | Project知識・ファイル添付等で読み込ませ、関連Issue/PRの最新内容を確認する |

接続なしのチャットが、勝手にローカルファイルや非公開Issueを読めるわけではありません。ツールの「指示を読む機能」と「コードを書き換える権限」も別です。読み込み確認前に複数エージェントへ編集権限を前提とした依頼を出さないでください。

## チャット型AIに渡す開始指示の例

> このリポジトリの `AGENTS.md` を共通開発規約として読み、`README.md` と `docs/README.md`、関連するIssue・PRを確認してください。現在のブランチと未マージのPRを区別し、担当範囲・変更予定のファイル・受入条件・検証方法を示してから作業してください。進捗はIssue/PRに残し、実行していないテストを成功と書かないでください。

これはコピペ可能な起動用の例であり、自動ファイル読み込み機構を追加するものではありません。

## 複数AIで同じIssueを扱うとき

1. **担当を分ける**：一つのIssueを複数PRに分ける場合、契約/ランタイム/API/部品/レビュー等、変更可能なファイルと依存PRを明記する。
2. **GitHubを正本とする**：目的と受入条件はIssue、コードと検証結果はPR、設計決定はADRに置く。別AIの会話ログは参考情報としてしか扱わない。
3. **並行変更を衝突させない**：複数エージェントが同じブランチへ無断でpushしない。共通API変更は先に契約をレビューし、依存PRのベースを明示する。
4. **検証を独立させる**：実装担当とレビュー担当は別セッションでもよいが、レビューはPR差分と実テストを参照する。前担当の「成功した」は検証証拠ではない。
5. **引き継ぎを記録する**：完了範囲、変更したパス、テスト結果、残課題、未マージ依存、次に必要な判断をPR本文/コメントに残す。

### 引き継ぎテンプレート

```text
Issue:
PR / branch / base:
目的・受入条件:
変更したファイル・公開契約:
検証コマンドと観測結果:
未実施の検証:
依存PR・衝突しそうなファイル:
未解決の設計判断・次の作業:
```

## 役割の例（固定ではない）

ChatGPTでIssueを整理し、Claude Code / Codexで別々の実装タスクを処理し、CopilotでPRレビューを補助することは可能です。ただし特定AIが常に設計者・実装者・承認者になるというルールはありません。**最終マージ判断は人間のリポジトリ管理者**が行います。

## 導入時の確認

- `AGENTS.md`、`CLAUDE.md`、`.github/copilot-instructions.md` がチェックアウト先に存在する。
- 各AIに「CoreへHTTPスクレイピングを追加してよいか」「CLIはHostを直接呼んでよいか」を質問し、どちらも不可と判断できる。
- 各AIに現在のIssue/PRと検証済み範囲を尋ね、未マージの変更をmain実装済みと誤認しない。
- CIでは `npm run check:agents` がファイル入口とリンクを検査する。ただし **AIプロバイダの実際の自動読込や指示順守をCIが保証するものではない**。
