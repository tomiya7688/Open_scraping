# グローバル非常停止

[設計書一覧](README.md)

改訂日：2026-09-27。**コアに置く唯一の安全機能は、実行内容を判定するフィルターではなく、人間が実行制御を強制的に取り戻すための非常停止である。**

## 1. 必須トリガー

アクティブrun中、アプリのウィンドウが最前面・背面・最小化のどの状態でも、次の入力をOSレベルで監視する。

1. `Esc` キー。
2. ユーザーによる物理的なマウス入力。移動、ボタン、ホイール等のどこまでをイベントとして受け取れるかはOSバックエンドで検証する。

トリガーは前面アプリへ通常どおり渡す受動監視を原則とし、入力を奪うためのフックにはしない。

## 2. 非常停止は取り外せない

非常停止はFlowConfig、検索部品、ブラウザ部品、フィルター、GUIの一機能として実装しない。コア／ランタイムが常に持つ制御プリミティブである。

- 部品は無効化できない。
- 派生構成は削除できない。
- GUIが閉じても作動する。
- 部品のイベントループが固まっていても、入力監視まで巻き込まれない構成にする。
- 自動復旧は非常停止より優先できない。
- 停止後の再開は明示操作だけ。

この原則は、データやコンテンツに対する安全フィルターをコアへ追加する根拠にはしない。内容の解析・選別は従来どおり任意部品である。

## 3. 停止シーケンス

トリガーを受けた監視系は、通常のフローキューを待たずに共有のemergency-stop状態を立てる。

1. 新規run・ノード・subcallを拒否。
2. 未開始の待機・予約を取消。
3. reload／reopen等の自動復旧を解除。
4. 全アクティブoperationへcancelを配送。
5. 有限の猶予後も応答しない所有ワーカー・managed browserをホストが終了。
6. `emergency_stopped` をジャーナルへ記録。
7. 確定済みデータを保持し、再armはユーザー操作まで行わない。

所有していないブラウザや他アプリを終了しない。外部サービスへ既に送られた要求まで取消できるとは保証しない。

## 4. 通常停止との違い

| 通常stop | emergency stop |
| --- | --- |
| GUI／CLI／APIからrun単位で要求 | OS入力または専用APIから全runへ発火 |
| 協調停止を基本とする | 強制終了まで進める |
| 自動復旧設定を利用可能 | 自動復旧を解除 |
| GUI・APIが操作入口になり得る | GUIのフォーカス／生存に依存しない |
| FlowConfigの実行制御 | FlowConfig外のランタイム不変条件 |

## 5. 合成入力との区別

外部部品がOSレベルでマウス・キーボードを合成する場合、それを人間の入力として誤認すると自分自身を止める可能性がある。

OSが合成イベントの識別情報を提供する場合は利用する。ホスト管理の入力注入には識別情報を付けられる設計を検討する。**ただし、物理入力かどうかを信頼できる形で区別できない環境で「完全に区別できる」と表示しない。**

誤作動を避けるためにユーザー入力を無視する方向へ安全条件を緩めない。対応可否をOS別に試験し、必要ならその環境を未対応にする。

## 6. フォーカス非依存の実装候補

### Windows

Microsoftの `SetWindowsHookExW` では `WH_KEYBOARD_LL` と `WH_MOUSE_LL` がglobal onlyのフックとして定義されている。[S14](references.md#s14)

### macOS

Core Graphicsの `CGEventTapCreate` でイベント監視を行う候補。[S15](references.md#s15) 必要なOS権限を明示し、許可がない場合はarm失敗として扱う。

### Linux／Wayland

XDG Desktop PortalのGlobalShortcutsは、フォーカス外でもショートカットを扱う。[S16](references.md#s16) 一方、同じAPIは任意のマウス入力ストリームを提供するものではない。

したがって、Waylandでは使用するcompositor／desktopがマウス要件を満たす方法を提供するか個別に検証する。Escだけ動く環境を完全対応と呼ばない。

## 7. 起動条件と状態

標準構成では、必要なグローバル監視をarmできなければ自動化runを開始しない。原因は権限不足、バックエンド未対応、監視プロセス異常などに分ける。

設定編集、フロー検証、部品管理等の非実行操作まで禁止する必要はない。

状態例：`disarmed`、`arming`、`armed`、`triggered`、`emergency_stopping`、`emergency_stopped`、`arm_failed`。

## 8. 受入テスト

- アプリが前面でない状態でEscを押し、停止する。
- 別アプリが前面の状態で物理マウスを操作し、停止する。
- GUIを終了してもランタイムが生きている間は停止できる。
- ブラウザ部品・通常ワーカーを意図的に固めても監視が反応する。
- 自動reopen中に非常停止すると、reopen後の処理を開始しない。
- 部品がcancelに応答しなくても、所有ワーカーだけを期限付きで終了する。
- プラグインやFlowConfigに非常停止を解除する設定を追加できない。
- OS権限を拒否した場合、arm失敗を表示し実行を開始しない。
- 物理入力とアプリ由来の合成入力の識別を、対応OSごとに試験する。

応答時間の数値目標はOS別プロトタイプで測定してから固定し、測っていない遅延保証を先に記載しない。
